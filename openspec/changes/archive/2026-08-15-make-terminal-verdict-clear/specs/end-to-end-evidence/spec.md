## MODIFIED Requirements

### Requirement: Terminal evidence is exact and stable
The system SHALL compare committed exact terminal bytes for codebase, diff,
package, directory, and file views at widths 120, 100, 80, and 50. Evidence
SHALL cover grouped checked digits, integer-safe halfway-up arithmetic, empty,
non-zero, and zero-attention verdicts, exact area counts and order, required
grouped and named real gaps, fixture/generated exclusions, the exact
Warning-glyph architecture row, and content-aware compact, stacked, and
middle-shortened rows. It SHALL prove exact
glyph code points and one-cell width, rejection of U+EC3F, `--color always`,
`--color never`, `NO_COLOR`, redirect behavior, glyph-only ANSI placement, and
equality after ANSI stripping.

#### Scenario: Terminal width changes
- **WHEN** each named report view is rendered at every required width
- **THEN** every result exactly matches reviewed bytes, preserves measurements, counts, cycle closure, history commit evidence, dependency state, commands, and recognizable identities, and every ANSI-stripped line fits the requested Unicode display width
- **AND** direct writer instrumentation records zero safety-fallback shortenings for reviewed default codebase, path, and diff flows at widths 120, 100, 80, and 50 while only a synthetic overflow records use of that safety path

#### Scenario: Styling policy changes
- **WHEN** forced, disabled, automatic, `NO_COLOR`, and redirected modes are compared for revised output
- **THEN** only the required glyphs receive exact colors and stripping ANSI reproduces plain bytes

### Requirement: Public command evidence covers every revised decision
Exact acceptance SHALL cover codebase, diff, package, directory, and file flows
for grouped checked digits; unsigned widened, integer-safe nearest-tenth
halfway-up arithmetic without a new report field; empty, zero-attention, and
non-zero verdicts; exact area counts and order without rates or shares; real
source gaps grouped in default root/package/directory views; every relevant
failed or recovered file once in `--all`; the selected affected file in its
file view; fixture/generated exclusions; verdict-affecting
primary/test/example/benchmark roles; the exact singular/plural Warning-glyph
architecture row; and content-aware rows. It SHALL cover full exact stderr
bytes including one newline, required status, and empty stdout for missing path,
missing ref, and `--all --json`, with no usage/help tail or leaked absolute path,
operating-system code, Git command/status/fatal output, parser text, or process
text. Existing section relevance, finding rank, architecture witnesses,
actionable history,
detail availability, and discover guidance SHALL remain checked without
deciding the next change's detailed relationship filtering.

JSON version-3 bytes, report and distribution facts, status classes, stream
placement, rank, serial/automatic bytes, work totals, analysis, allocation, and
performance evidence SHALL prove unchanged behavior.

#### Scenario: Human output is audited
- **WHEN** snapshots, help, errors, warnings, and README examples are checked
- **THEN** the exact verdict and safe phrases appear while old quality wording, area rates, shares, bars, fixed-tier assumptions, false coverage gaps, repeated warning text, and leaked implementation diagnostics do not

#### Scenario: Machine and analysis output is audited
- **WHEN** revised terminal flows run through the complete public matrix
- **THEN** JSON bytes, report facts, exit classes, streams, rank, work counts, analysis facts, allocations, and resource evidence remain unchanged

### Requirement: Three workload families have privacy-safe acceptance
After public proof passes, aggregate read-only review SHALL cover self, a
private mixed application, and a private Rust workspace. Each review SHALL
check verdict clarity, fixture/generated-versus-real coverage meaning, the exact
architecture warning, fact preservation, and absence of safety-fallback
shortening. Committed evidence SHALL name only workload family and aggregate
outcome categories and SHALL contain no private name, path, source, Git
identity, history, or raw terminal output.

#### Scenario: Self is reviewed
- **WHEN** default output is inspected read-only
- **THEN** its verdict and leading findings are useful, warnings reflect only real gaps, and required facts survive content-aware layout

#### Scenario: Private mixed application is reviewed
- **WHEN** default output is inspected read-only
- **THEN** primary application findings remain useful, generated exclusions do not create false gaps, test source still affects the verdict, and no required fact is silently lost

#### Scenario: Private Rust workspace is reviewed
- **WHEN** default output is inspected read-only
- **THEN** useful Rust findings remain visible, the architecture warning is grouped correctly, and no required fact is silently lost
